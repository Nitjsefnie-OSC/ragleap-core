# ragleap-phone, Phase 0: provider interface and audio contract (draft)

Status: draft for discussion (RFC issue #814). Nothing below is built; every item is **planned**.
Evidence tags: [verified] seen in the repo or public documentation; [plan] intention; [unverified] not checked.

## 1. Scope

ragleap-phone connects phone calls to RagLeap. Speech (speech to text, text to speech) stays in ragleap-voice.
This note defines two contracts: the provider adapter (how a call source plugs in) and the audio and event
stream between a call and the speech layer. It does not choose a backend; that is the comparison in section 6.

## 2. Connection modes

1. Any SIP trunk through a self-hosted backend. [plan]
2. The customer's own PBX and lines, on premises, possibly without internet. [plan]
3. No phone network: SIP or web calls between apps. [plan]
4. Twilio stays as one adapter so the current behaviour is kept. [plan]

Software alone cannot join the phone network: a real number needs a carrier or a telecom line. Emergency calling is never supported.

## 3. Provider adapter (small abstract class)

    class Adapter:
        name: str
        capabilities: Capabilities     # transport, codecs, dtmf, barge_in, max_concurrent_calls
        async def run(self, on_call) -> None      # accept calls, call on_call(Call) for each
        async def close(self) -> None

    class Call:
        id: str                        # generated by our side; never taken from the remote party
        direction: "inbound" | "outbound"
        async def audio_in(self) -> AsyncIterator[Frame]
        async def send_audio(self, frame) -> None
        async def clear_playback(self) -> None    # barge-in: drop queued audio at once
        async def hangup(self) -> None
        events: AsyncIterator[Event]

Rules for every adapter:
- It authenticates the source of each call before audio is processed, in the way its transport allows.
- It enforces limits: connections, call length, frames per second.
- It never logs audio, transcripts or phone numbers by default.
- It listens on localhost unless the operator opts in.

## 4. Audio and event contract

- Frames: PCM 16-bit little-endian, mono, 20 ms. The phone side is 8 kHz. Mu-law and A-law are converted at the adapter edge.
- The bridge resamples 8 kHz to the 16 kHz that most speech models expect, and back. The resampler and its quality are to be measured. [plan]
- Events: call.started, dtmf (digit), playback.finished (the equivalent of Twilio's mark), call.ended, error.
- Every frame carries a monotonic timestamp so latency can be measured end to end.

## 5. What ragleap-phone needs from ragleap-voice

These are requirements for the Stage 3 streaming design in the 0.1.0 API draft (#762), which reserves the names below:
- `transcribe_stream(frames)`: partial and final transcripts from a frame stream, with an end-of-turn signal.
- `synthesize_stream(text)`: audio chunks as they are produced, cancellable within one frame.
- Both accept 16 kHz and report the time to first partial result and the time to first audio.
- No silent fallback to a hosted service. A phone deployment may run with no internet.
- Targets are measured on real phone audio and published. No number is promised here.

## 7. Out of scope here

Recording, voice cloning on calls (consent store, issue #763), country telephony rules (country champions), emergency calling.

## 8. Open questions

3. Echo handling and barge-in: who owns the echo reference?
4. Which SIP trunk and number serve test calls, and who pays?
5. Do we need an OpenAI-compatible endpoint in ragleap-voice so existing stacks can use it?
